## 📖 معرفی

**VPN Hunter** یک بات فروش کانفیگ V2Ray برای تلگرام است که با پایتون و فریمورک [aiogram 3](https://docs.aiogram.dev/)
نوشته شده. هدف این پروژه، جایگزینی فرآیند دستی فروش کانفیگ (که معمولاً با پیام دادن مستقیم به فروشنده انجام می‌شود)
با یک فروشگاه تلگرامی کاملاً خودکار است: کاربر دسته‌بندی و محصول را انتخاب می‌کند، رسید پرداخت می‌فرستد، و بعد از
تایید ادمین، کانفیگ به‌صورت خودکار و یکتا برایش ارسال می‌شود — بدون هیچ دخالت دستی در ارسال کانفیگ.

پروژه به‌صورت **تک‌فایلی نیست** و ساختار ماژولار دارد (هندلر کاربر، هندلر ادمین، دیتابیس، کیبورد و ...) تا نگهداری
و توسعه‌ی آن ساده باشد؛ همچنین دیتابیس آن **SQLite** است، یعنی نیازی به نصب و نگهداری هیچ سرور دیتابیس جداگانه‌ای
(مثل MySQL یا PostgreSQL) وجود ندارد.

## 🧱 ساختار پروژه

```
Newbotshop/
├── main.py              # نقطه ورود و اجرای بات
├── config.py             # خواندن تنظیمات از .env (توکن، آیدی مالک، مسیر دیتابیس)
├── database.py           # تمام عملیات دیتابیس (SQLite) + migration خودکار
├── keyboards.py          # ساخت دکمه‌های شیشه‌ای و منوهای Reply/Inline
├── states.py             # مراحل مکالمه (FSM States)
├── handlers_user.py      # منطق مربوط به کاربر عادی
├── handlers_admin.py     # منطق پنل مدیریت و نمایندگان
├── requirements.txt      # وابستگی‌های پایتون
├── install.sh            # نصب/آپدیت خودکار + ساخت سرویس systemd
├── update.sh             # آپدیت سریع بعد از تغییرات (git pull + restart)
├── manage.sh             # پنل مدیریت متنی رنگی (منوی شماره‌دار)
└── .env                  # توکن و آیدی ادمین (هرگز داخل گیت‌هاب قرار نمی‌گیرد)
```

**پشته‌ی فنی (Tech Stack):**
- زبان: Python 3.10+
- فریمورک بات: [aiogram 3.20+](https://docs.aiogram.dev/) (async, پشتیبانی از FSM و رنگ‌آمیزی دکمه‌ها)
- دیتابیس: SQLite (بدون نیاز به سرور جداگانه)
- مدیریت پروسه: systemd (اجرای دائمی و ری‌استارت خودکار بعد از ری‌بوت سرور)

## ⚙️ پیش‌نیازها

- یک سرور لینوکسی (Ubuntu/Debian توصیه می‌شود) با دسترسی روت یا `sudo` — یک VPS ساده کافیست
- دسترسی دائمی به اینترنت (بات باید همیشه روشن باشد)
- یک توکن بات تلگرام از [@BotFather](https://t.me/BotFather)
- آیدی عددی تلگرام خودتان به‌عنوان مالک بات (از [@userinfobot](https://t.me/userinfobot) قابل دریافت است)

> نصب Python، pip، venv و git نیازی به انجام دستی ندارد — اسکریپت `install.sh` خودش همه را نصب می‌کند.

## 🚀 نصب سریع (یک خط دستور)

ساده‌ترین راه نصب روی یک سرور تازه، اجرای همین یک دستور است:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/mehdirafatpanah/Newbotshop/main/install.sh)
```

این اسکریپت به‌صورت کاملاً خودکار:
1. `git`, `python3`, `pip`, `venv` را در صورت نیاز نصب می‌کند
2. پروژه را از گیت‌هاب کلون می‌کند (یا اگر قبلاً نصب بوده، فقط `git pull` می‌زند)
3. محیط مجازی پایتون (`venv`) را می‌سازد و پکیج‌های `requirements.txt` را نصب می‌کند
4. **فقط بار اول** توکن بات و آیدی ادمین را از شما می‌پرسد و فایل `.env` را می‌سازد
5. یک سرویس `systemd` به نام `v2raybot` می‌سازد تا بات همیشه در پس‌زمینه اجرا بماند و بعد از هر ری‌بوت سرور
   خودش دوباره بالا بیاید
6. بات را (ری)استارت می‌کند و وضعیت نهایی را نمایش می‌دهد

اجرای این اسکریپت **idempotent** است، یعنی هم برای نصب اولیه و هم برای آپدیت‌های بعدی قابل استفاده است — دوباره
اجرا کردنش هیچ آسیبی نمی‌زند.

### نصب دستی (به‌جای اسکریپت خودکار)

اگر ترجیح می‌دهید مرحله‌به‌مرحله و دستی نصب کنید:

```bash
# ۱. کلون پروژه
git clone https://github.com/mehdirafatpanah/Newbotshop.git ~/v2ray_bot
cd ~/v2ray_bot

# ۲. ساخت محیط مجازی و نصب وابستگی‌ها
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# ۳. تنظیم فایل .env
cp .env.example .env
nano .env
```

مقادیر داخل `.env` را این‌طور تنظیم کنید:
```env
BOT_TOKEN=توکن_واقعی_بات
OWNER_ID=آیدی_عددی_شما
```

```bash
# ۴. اجرای بات (برای تست سریع)
python main.py
```

⚠️ فایل `.env` **هرگز** نباید وارد گیت‌هاب شود (در `.gitignore` قرار دارد). فقط `.env.example` (بدون مقدار واقعی)
داخل مخزن قرار می‌گیرد.

#### اجرای دائمی به‌صورت دستی (بدون systemd)

برای تست سریع، یکی از روش‌های زیر کافیست تا با بستن ترمینال، بات خاموش نشود:

```bash
# با screen
screen -S v2raybot
python main.py
# سپس Ctrl+A و بعد D برای خروج بدون بستن بات

# یا با nohup
nohup python main.py > bot.log 2>&1 &
```

> برای پروداکشن **همیشه از روش systemd (نصب خودکار بالا یا `manage.sh`) استفاده کنید**، چون در صورت کرش کردن
> بات یا ری‌استارت سرور، خودش دوباره بالا می‌آید؛ روش‌های `screen`/`nohup` این قابلیت را ندارند.

(شبیه ابزارهای شناخته‌شده‌ای مثل مرزبان یا Reality-EZ).

### اجرا روی یک سرور تازه (بدون نصب قبلی)
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/mehdirafatpanah/Newbotshop/main/manage.sh)
```

### اجرا بعد از نصب
```bash
bash ~/v2ray_bot/manage.sh
```

### امکانات منو

```

[9] تغییر توکن یا آیدی ادمین       — بدون نیاز به ویرایش دستی فایل .env
[0] خروج
```

## 🔄 آپدیت

### روش پیشنهادی: `update.sh`
اگر تغییری در کد پروژه دادید و می‌خواهید روی سرور اعمال کنید:

```bash
cd ~/v2ray_bot
git add .
git commit -m "توضیح کوتاه تغییر"
git push
./update.sh "توضیح کوتاه تغییر"
```

اسکریپت `update.sh` به‌صورت خودکار: تغییرات را `commit`/`push` می‌کند (اگر قبلاً انجام نداده باشید)،
پکیج‌های پایتون را آپدیت می‌کند، و سرویس بات را ری‌استارت می‌کند.

### روش جایگزین: همان دستور نصب
از آن‌جا که `install.sh` idempotent است، اجرای دوباره‌ی همان دستور نصب هم کار آپدیت را انجام می‌دهد:
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/mehdirafatpanah/Newbotshop/main/install.sh)
```

### یا از داخل پنل مدیریت متنی
```bash
bash ~/v2ray_bot/manage.sh
# سپس گزینه‌ی [2] آپدیت بات را انتخاب کنید
```

> ⚠️ اگر دیتابیس (`bot_database.db`) از قبل روی سرورتان وجود دارد، نیازی به هیچ کار دستی نیست — با هر آپدیت،
> ستون‌های جدید به‌صورت خودکار و **بدون از‌دست‌رفتن داده‌های قبلی** به دیتابیس اضافه می‌شوند (migration خودکار
> در `database.py`).

## 🩺 عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| بات بالا نمی‌آید | `sudo journalctl -u v2raybot -n 50 --no-pager` را بزنید و آخرین خطا را بررسی کنید |
| خطای `can't parse entities` در لاگ | یعنی متنی حاوی کاراکتر خاص Markdown (مثل `_`) بدون اسکیپ در پیام تلگرامی قرار گرفته؛ در نسخه فعلی پروژه این مورد با تابع `md_escape()` در `config.py` مدیریت می‌شود |
| `BOT_TOKEN تنظیم نشده است` | فایل `.env` را بررسی کنید؛ باید کنار `main.py` باشد و مقدار `BOT_TOKEN` صحیح داشته باشد |
| بات بعد از ری‌بوت سرور خاموش می‌ماند | مطمئن شوید سرویس systemd فعال است: `sudo systemctl enable v2raybot` |
| تغییرات کد اعمال نمی‌شود | بعد از هر تغییر، حتماً `sudo systemctl restart v2raybot` یا `./update.sh` را اجرا کنید |

**دستورات پرکاربرد:**
```bash
sudo systemctl status v2raybot     # وضعیت بات
sudo journalctl -u v2raybot -f     # لاگ زنده
sudo systemctl restart v2raybot    # ری‌استارت
sudo systemctl stop v2raybot       # توقف
```

## 📚 مستندات تکمیلی قابلیت‌ها

<details>
<summary><strong>👛 کیف پول</strong></summary>

کاربر از بخش «کیف پول من» موجودی خود را می‌بیند و می‌تواند با دکمه‌ی «➕ شارژ کیف پول»، مبلغ دلخواه را وارد
و رسید کارت‌به‌کارت ارسال کند. پس از تایید ادمین (از پنل مدیریت یا مستقیم از پیام فوروارد‌شده)، مبلغ به کیف
پول اضافه می‌شود. این موجودی (چه از شارژ دستی، چه از پورسانت زیرمجموعه‌گیری) در خریدهای بعدی به‌صورت خودکار
کسر می‌شود؛ اگر موجودی کل قیمت را پوشش دهد، نیازی به ارسال رسید نیست.
</details>

<details>
<summary><strong>🤝 زیرمجموعه‌گیری (رفرال)</strong></summary>

هر کاربر یک لینک اختصاصی دارد: `https://t.me/USERNAME_BOT?start=ref<آیدی_عددی_کاربر>`. با اولین خرید
تایید‌شده‌ی هر زیرمجموعه، درصدی از مبلغ (پیش‌فرض ۱۰٪، قابل تغییر از پنل مدیریت) به‌صورت اعتبار کیف پول به
دعوت‌کننده تعلق می‌گیرد و در خرید بعدیِ او خودکار کسر می‌شود.
</details>

<details>
<summary><strong>🎟 کد تخفیف</strong></summary>

از پنل مدیریت → «مدیریت کدهای تخفیف» → «ساخت کد تخفیف جدید»، دو نوع پشتیبانی می‌شود: درصدی (`percent 20`)
یا مبلغ ثابت (`fixed 50000`)، با سقف تعداد استفاده قابل تنظیم (۰ = نامحدود). کد تخفیف و کیف پول با هم قابل
جمع هستند؛ اگر سفارشی رد شود، هم کیف پول مصرف‌شده و هم سهمیه‌ی کد به‌طور خودکار برمی‌گردد.
</details>

<details>
<summary><strong>🏪 سیستم نمایندگی (Multi-Agent)</strong></summary>

از پنل مدیریت → «مدیریت نمایندگان» یک نماینده اضافه کنید (آیدی عددی کسی که قبلاً `/start` را زده، به‌همراه
یک نام). نماینده با `/start` مجدد، دکمه‌ی «پنل نمایندگی» را می‌بیند و می‌تواند مستقل از فروشگاه اصلی:
دسته‌بندی/محصول بسازد، کانفیگ اضافه کند، شماره کارت اختصاصی تنظیم کند، سفارش‌های مشتری‌های خودش را تایید/رد
کند و آمار فروش خودش را ببیند. هر نماینده یک لینک اختصاصی دارد:
`https://t.me/USERNAME_BOT?start=agent<آیدی_عددی_نماینده>`. مالک بات همیشه دسترسی نظارتی کامل دارد.

> کانفیگ تست، کد تخفیف، زیرمجموعه‌گیری و کیف پول در حال حاضر سراسری هستند و به فروشگاه اصلی تعلق دارند
> (جداگانه برای نمایندگان پیاده‌سازی نشده‌اند).
</details>

<details>
<summary><strong>🎨 رنگ‌آمیزی دکمه‌ها</strong></summary>

از تاریخ ۹ فوریه ۲۰۲۶ (Bot API 9.4)، تلگرام قابلیت رنگ‌آمیزی دکمه‌ها (فیلد `style`) را اضافه کرده و این پروژه
از آن استفاده می‌کند. از پنل مدیریت → «ویرایش متن دکمه‌ها» → «تغییر رنگ»، برای هر دکمه یکی از رنگ‌های
🔵 آبی (`primary`)، 🟢 سبز (`success`)، 🔴 قرمز (`danger`) یا پیش‌فرض/خاکستری قابل انتخاب است. این قابلیت
نیازمند `aiogram>=3.20.0` (که در `requirements.txt` تنظیم شده) و اپلیکیشن تلگرام به‌روز است؛ در نسخه‌های
خیلی قدیمی تلگرام، دکمه‌ها با رنگ پیش‌فرض نمایش داده می‌شوند. تغییر رنگ Reply Keyboard از پیام بعدی بات
(مثلاً بعد از `/start` مجدد) قابل مشاهده است.
</details>

## 🔐 امنیت

- فایل `.env` (شامل `BOT_TOKEN` و `OWNER_ID`) هرگز نباید داخل گیت‌هاب یا هر مخزن عمومی دیگری قرار بگیرد؛
  این فایل در `.gitignore` است و به‌صورت پیش‌فرض نادیده گرفته می‌شود.
- اگر مخزن این پروژه **Public** است، قبل از هر `push` مطمئن شوید `.env` و `bot_database.db`
  (که حاوی اطلاعات کاربران و سفارش‌هاست) داخل کامیت‌ها نیستند.
- اگر توکن بات به هر شکلی (چت، اسکرین‌شات، کامیت اشتباه) لو رفت، فوراً از طریق
  [@BotFather](https://t.me/BotFather) دستور `/revoke` را بزنید و توکن جدید بگیرید.
- توکن یا هیچ اطلاعات حساس دیگری را مستقیم داخل کد ننویسید؛ همیشه در `.env` نگه دارید.
